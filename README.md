## Folder Guide — What It Means & What It Does

### 1. Backend Architecture (`backend/src/TeamTaskManager.Api/`)

The backend is built with **ASP.NET Core (.NET 8/9)** and **Entity Framework Core (PostgreSQL)** following **Clean/Layered Architecture**. Every directory has a single, isolated responsibility:

| Folder | What It Means | What It Does (Responsibilities & Examples) |
|---|---|---|
| **`Models/`** | **Domain Entities** | Core business objects that represent data in memory and map directly to PostgreSQL tables via EF Core. Contains domain rules and navigation properties.<br>• *Examples:* `ApplicationUser.cs` (Identity User), `Workspace.cs`, `Project.cs`, `ProjectMember.cs`, `TaskItem.cs`, `Comment.cs`, `Label.cs`, `ProjectRole.cs`, `TaskItemStatus.cs`. |
| **`Data/`** | **Persistence & DbContext** | Configures database connectivity, sets up table schemas, unique constraints, and foreign key behaviors (e.g. `Cascade` for tasks when deleting a project, vs `Restrict` when deleting users).<br>• *Examples:* `AppDbContext.cs` (inherits from `IdentityDbContext<ApplicationUser, IdentityRole<Guid>, Guid>`). |
| **`Migrations/`** | **Schema Version Control** | Timestamped migration classes generated by EF Core tools. Records every change to database tables, indexes, and column types so schemas can be reproduced deterministically across any environment.<br>• *Examples:* `AddUsersAndProjectMembers.cs`, `AddTaskItems.cs`, `AddCommentsAndLabels.cs`. |
| **`Contracts/`** | **Data Transfer Objects (DTOs)** | Strongly typed input commands and output views transferred over HTTP. Decouples internal database entities from external API contracts to prevent over-posting and data leaking.<br>• *Examples:* `Contracts/Auth/RegisterRequest.cs`, `LoginRequest.cs`, `AuthResponse.cs`. |
| **`Controllers/`** | **API Endpoints & Routing** | HTTP presentation layer. Receives requests, handles model binding, runs validation, executes application services, and returns appropriate HTTP status codes (`200 OK`, `201 Created`, `400 Bad Request`, `401`, `403`).<br>• *Examples:* `AuthController.cs` (`/api/v1/auth/register`, `/api/v1/auth/login`), `TasksController.cs`. |
| **`Auth/`** | **Authentication Infrastructure** | Handles identity verification (*who the user is*). Contains JWT token generation (HMAC-SHA256), token claims builder, refresh token rotation, and password hashing security.<br>• *Examples:* `JwtService.cs`, `TokenGenerator.cs`, `RefreshTokenHandler.cs`. |
| **`Authorization/`** | **Resource-Based Access Control** | Enforces permission boundaries (*what an authenticated user is allowed to do*). Ensures project isolation so users cannot read or mutate tasks/projects they do not belong to, completely preventing IDOR attacks.<br>• *Examples:* `ProjectMemberRequirement.cs`, `ProjectMemberAuthorizationHandler.cs`. |
| **`Services/`** | **Application Business Logic** | Orchestrates domain operations, enforces workflow invariants (e.g. valid task status movements), and integrates external cloud APIs like Google Gemini for AI-driven task decomposition.<br>• *Examples:* `TaskItemService.cs`, `GeminiAiService.cs`, `ProjectService.cs`. |
| **`Common/`** | **Cross-Cutting Utilities** | Reusable shared abstractions across the entire API, including RFC 7807 `ProblemDetails` error structures, pagination envelopes, custom exception definitions, and DateTime helpers.<br>• *Examples:* `ApiResponse<T>`, `PagedList<T>`, `GlobalExceptionFilter.cs`. |
| **`Properties/`** | **Runtime Launch Profiles** | Contains local development server environment configurations, ASP.NET Core environment flags (`ASPNETCORE_ENVIRONMENT=Development`), and local port bindings.<br>• *Examples:* `launchSettings.json`. |
| **`backend/tests/`** | **Automated Test Suite** | Contains unit tests and integration tests that verify authentication flows, controller responses, and resource authorization handlers.<br>• *Examples:* `TeamTaskManager.Api.Tests`. |

### 2. Frontend Architecture (`frontend/`)

The frontend is built with **Next.js (App Router)**, **React 19**, **TypeScript**, and **Tailwind CSS**, organized using a **Feature-Driven** modular structure:

| Folder | What It Means | What It Does (Responsibilities & Examples) |
|---|---|---|
| **`app/`** | **Next.js App Router (Routing & Layouts)** | Next.js directory-based routing system. Folders represent URL segments, while special files define layouts, root pages, loading indicators, and error boundaries.<br>• *Key files:* `layout.js` (global root layout, font loading), `page.js` (dashboard/homepage), `globals.css` (Tailwind styles). |
| **`features/`** | **Domain-Driven Feature Slices** | Self-contained, domain-specific modules encapsulating UI components, forms, and local state management for each core feature: |
| ├── `features/auth/` | **User Authentication Slice** | Login form, Registration form, Session state, protected route auth guards. |
| ├── `features/workspaces/` | **Workspace Scoping Slice** | Workspace selector dropdown, workspace creation modals, multi-tenant boundaries. |
| ├── `features/projects/` | **Project Management Slice** | Project grid cards, project creation drawer, member invite dialogs. |
| ├── `features/tasks/` | **Task Board & Lifecycle Slice** | Jira-style Kanban board (Todo, InProgress, Review, Done columns), drag-and-drop task cards, task detail view, and the AI subtask breakdown assistant modal. |
| └── `features/comments/` | **Collaboration Slice** | Real-time discussion thread beneath tasks, comment author avatars, timestamp formatting. |
| **`components/`** | **Reusable Generic Components** | Generic UI building blocks independent of business domain: |
| ├── `components/ui/` | **Atomic UI Primitives** | Headless accessible UI components (buttons, dialogs, inputs, dropdown menus, badges, tabs, cards) based on Radix UI & shadcn/ui. |
| └── `components/shared/` | **App Shell Elements** | Shared application chrome used across all pages (Navbar, Sidebar, ThemeToggle, UserAvatar). |
| **`hooks/`** | **Custom React Hooks** | Encapsulates reusable stateful logic and browser events (e.g. `useAuth.js`, `useTasks.js`, `useDebounce.js`). |
| **`lib/`** | **Shared Libraries & Utilities** | Third-party client instantiations and helper functions: |
| └── `lib/api/` | **HTTP Client & Interceptors** | Configured API client (Axios/Fetch) with request interceptors to automatically attach `Authorization: Bearer <token>` and response interceptors for silent refresh token rotation on 401 errors. |
| **`public/`** | **Static Web Assets** | Static files served directly by the browser without processing (SVGs, logos, favicon). |

## Running the Backend

From the repository root:

```bash
cd backend/src/TeamTaskManager.Api
dotnet run
```

Or from the `backend/` folder:

```bash
cd backend
dotnet run --project src/TeamTaskManager.Api
```

Swagger UI is available at `https://localhost:7196/swagger` (or configured port in `Properties/launchSettings.json`).

To run backend tests:

```bash
cd backend
dotnet test
```

## Running the Frontend

From the repository root:

```bash
cd frontend
npm run dev
```

The application will start on [http://localhost:3000](http://localhost:3000).
